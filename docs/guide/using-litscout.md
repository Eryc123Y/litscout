# Using LitScout

Start in **Today** for the morning brief, use **Library** to keep papers, and open Obsidian to develop the ideas they give you. Use a deployment that includes the features you want to try, and see the [self-host guide](../self-host.md) for setup and credentials.

## A reading day

1. **Let the schedule run.** A scheduled run checks arXiv, fills in missed listings, fetches Hugging Face and the watched venues, and deduplicates and shortlists papers by topic. With an agent client configured, it also writes summaries and a morning brief once a listing is ready. Late listings stay under their arXiv date. On your own server the timers start the runs; on Cloudflare a scheduler on your computer does. [Daily runbook](../runbook/daily.md#command-order)
2. **Read the Morning brief.** Start with the radar for your projects, scan the topic picks and look at the suggestions. The weekday delivery target is 11:30 in the instance time zone. If the brief is pending, you can still browse the papers below it. Use the topic or source filters to narrow the feed.
3. **Open and keep papers.** Select a row to read its summary, then open the full Paper page or follow a source link. Rate a paper up or down to inform future briefs, star it to find it again, and use **Save to library** to keep it in Library. Add a quick note to remember why it matters. [Daily runbook](../runbook/daily.md#command-order)
4. **Turn reading into a vault task.** On a paper, capture a new idea with the paper attached or link the paper to an existing idea. You can also accept a suggestion from Today or Ideas. Check the pending work on **Vault sync**. The next write-enabled sync on the computer that holds the vault applies queued requests and adds captures to `Inbox.md` for you to develop in Obsidian.

## Pages

From tablet width up, a day reads in two columns that scroll on their own: the paper list on the left and the reader on the right. The reader shows the Morning brief until you open a paper; **Back to brief** or Escape returns to it, and `j` / `k` move between papers without moving the page. Drag the divider between the columns (or focus it and use the arrow keys) to size the list; the width is kept in your browser. The topics sit in one scrolling line above the list, and the heading says how old the listing is (**Yesterday**, **4 days ago**). On other pages, papers and notes open in a side panel beside the page; Escape or **Close panel** puts it away and the page stays where it was. Display times for the brief, mirror, link checks and sync use the instance time zone, while feed dates keep the original listing date.

On a phone, use the bottom bar for **Today**, **Days**, **Library** and **Ideas**. Open **More** for the other pages. The Morning brief starts collapsed and extra feed filters sit under **Filters**. Tap a paper to read it full screen. **Back** returns you to the same row and scroll position.

## Import papers from Zotero

In Zotero, choose **Export Collection** or **Export Items**. Export as **Better BibTeX** with the plugin, or use Zotero's built-in **CSL JSON**. Use UTF-8. Exported tags and collection names become Library tags such as `zotero/Reading`. To include collection names, use a Better BibTeX export with a `groups` or `collections` field.

Use a LitScout token with the `write` scope. Preview the counts, then import the same file when they look right.

```bash
litscout library import "Zotero export.bib" --dry-run
litscout library import "Zotero export.bib"
litscout library import "Zotero export.json" --format csl --dry-run --json
```

The command accepts up to 5 MB and 5,000 entries. It links by DOI, then arXiv ID, then a normalized title confirmed by an author or the publication year. New records without a usable identifier or confirmed match appear as unverified in Library. The preview counts new records, links to existing papers, duplicates within the file, unverified records and invalid entries. For a malformed BibTeX entry it also reports the starting line.

If the result is `budget-short`, rerun the same import with the unchanged file and format after the displayed UTC reset time. Use the same command after an interruption to resume from the last saved batch.

## What lives where

| Owner                           | What is kept there                                                                                               | What crosses over                                                                                                                                                                                                                                   |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Obsidian vault**              | Idea and draft text, paper and project note bodies, Inbox, plans and private notes.                              | Sync sends allowed titles, frontmatter, paths and hashes to a private read-only index in LitScout, plus project, idea and draft bodies when `vault.uploadBodies` is on. Local agents can work with full notes on the computer that holds the vault. |
| **LitScout**                    | Paper records and links, summaries, digests, library state and quick notes.                                      | Write-enabled sync copies digests to digest notes and summary, link and quick-note details to managed blocks in matching paper notes.                                                                                                               |
| **LitScout → Obsidian handoff** | Captures, accepted suggestions and requests to make a note, link a paper, move an idea or add to a reading list. | Sync sends captures to `Inbox.md` and applies requests. Conflicting status changes are flagged for review. New paper links can be added to an edited list.                                                                                          |
| **alphaXiv**                    | Original library, notes and highlights.                                                                          | The optional mirror copies library metadata and annotation counts or flags. Note and highlight text stay in alphaXiv.                                                                                                                               |

During shadow mode, a dry run changes neither side. A regular sync with `vault.write: false` publishes the private index and report. File writes are made by sync on the computer that holds the vault, when enabled. [Ownership decision](../adr/0003-vault-first-ownership.md)

## Use LitScout in Claude Code, claude.ai and Codex

Use the Worker origin's `/mcp` endpoint. In **Claude Code**, add it as an HTTP server and choose **Authenticate** from `/mcp`. In **claude.ai**, add a custom connector under **Settings → Connectors**, connect it and enable it for the chat. In **Codex**, register it as a streamable HTTP server and complete OAuth. Use the one-time code on LitScout's consent page and approve the scopes the client needs. Pair again if an older grant lacks library permissions. Claude Code and Codex also support a dedicated API token. [Pairing and scopes](../self-host.md#10-pair-an-mcp-client)

| Ask the client to…                                                                                   | Tools                                                                                                                    |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Read a day: its morning brief, counts and papers, or its triage queue; list days and the behind ones | `get_day`, `list_days`                                                                                                   |
| Check runs, today's write budget and (with research tools and write access) vault sync               | `get_status`                                                                                                             |
| Look up a paper, find a saved paper or read its summary and notes                                    | `lookup_paper`, `search_library`, `get_paper`, `list_notes`                                                              |
| Read monthly topic trends                                                                            | `get_trends`                                                                                                             |
| Save a paper (or queue it in To read), change its status or tags, or remove it                       | `save_paper`, `update_library_item`, `remove_from_library`                                                               |
| Record, edit or delete a note, update reading state, or skip a paper                                 | `add_note`, `edit_note`, `delete_note`, `mark_paper`                                                                     |
| Search the literature, trace citations, or check an author, reviews or venue                         | `search`, `paper_links`, `get_author`, `coauthorship`, `reviews`, `venue`                                                |
| Find a project, idea, draft or suggestion in your research index, or read its note                   | `research_context`, `list_ideas`, `get_idea`, `get_note`, `list_suggestions`, `list_working_papers`, `get_working_paper` |
| Capture an idea, move it to another status, or act on a suggestion                                   | `capture_idea`, `set_idea_status`, `resolve_suggestion`                                                                  |
| Queue a paper link, reading-list entry or paper note, and see or cancel what is queued               | `request_link`, `add_reading`, `make_paper_note`, `list_vault_requests`, `cancel_vault_request`                          |

Reads require `read` and writes require `write`. Library and note edits take the record's `rev` and refuse a stale one. Vault requests wait in a queue and reach the Obsidian vault only when sync runs with `vault.write` on. General literature search and the research index and its actions require `mcp.researchTools: true`, which defaults off. For discussion that needs full Obsidian note text, use Claude Code inside the vault. [Ownership decision](../adr/0003-vault-first-ownership.md)

### Optional API-key mode for self-hosters

The scheduler can keep using its signed-in local clients. API-key mode defaults off and requires no setup. Self-hosters can choose `api` for summaries or digests, or add it as a fallback. The provider receives the prompts and bills that account. Set the key in the scheduler's environment and configure daily request and token limits. [API-key setup](../self-host.md#use-your-own-api-key-for-the-writing-agent)

## Weekly and occasional tasks

Run these from the scheduler's checkout and set `CONFIG` to its trusted configuration path. Set `BACKUP` to a private gzip destination and `READING_DAY` to the affected arXiv date as needed. [Daily runbook](../runbook/daily.md#preconditions)

- **Older papers.** Days and Trends keep archived titles and their original feed dates. With M4h deployed, open an archived paper privately and choose **Load details** to fetch available authors and abstract for that visit. Saving, rating or linking can restore a full record under the same ID. The old summary may be unavailable. [Paper reader](../../apps/web/src/Paper.tsx) · [Retention settings](../self-host.md#paper-retention)
- **Weekly.** Read the Sunday report for missed dates, topic and venue counts and timing. Save a private export from Settings or run `pnpm exec litscout backup --out "$BACKUP" --config "$CONFIG"` with write access. Verify it offline with `pnpm exec litscout backup --verify "$BACKUP"`. Keep a separate copy of the vault files. [Weekly run](../runbook/daily.md#command-order)
- **When a run is broken.** Use `pnpm exec litscout doctor --config "$CONFIG"` to check configuration, services, clients and vault access. If `pnpm exec litscout daily status --json --config "$CONFIG"` shows a pending day, check the scheduled `daily fetch` result for the reason. [Daily runbook](../runbook/daily.md#failure-and-usage-gate-handling)
- **When papers are rejected.** A completed fetch lists quarantined papers under `invalid` with the date, ID and reason. Record the omission and continue with valid papers. If every paper is rejected or the count exceeds the larger of 20 papers and 10% of the day's total, fetch reports an error and leaves the day pending. Keep the saved crawl and both cursors. Investigate the reported cause, then retry the same fetch after the cause is fixed. Dates deferred by the default 20-minute crawl deadline are retried on later runs.
- **When the write budget is tight.** Run `pnpm exec litscout budget --json --config "$CONFIG"` for the UTC-day balance and stale reservation recovery. With D1 Analytics access, `pnpm exec litscout budget --reconcile --json --config "$CONFIG"` also records any higher write total for this database once pending reservations are settled or final. If the budget stops a run, keep its checkpoint and resume after the reported reset. [Free-plan operations](../self-host.md#cloudflare-free-plan)
- **To read monthly trends from a terminal.** Run `pnpm exec litscout trends --month 2026-11 --config "$CONFIG"` with `read` access. Add `--topic` to select a topic. The scheduled run refreshes Trends after final digest handling.
- **When a day closed before arXiv arrived.** Preview with `pnpm exec litscout day reopen "$READING_DAY" --dry-run --config "$CONFIG"`. Applying needs write access and confirmation and removes that day's daily digests so the crawl and brief can finish again. [Recovery steps](../runbook/daily.md#a-day-was-closed-before-its-arxiv-listing-arrived)
- **Before switching off the old run.** Use `pnpm exec litscout cutover check --config "$CONFIG" --backup "$BACKUP"` to check the Worker run records and sidecar comparisons, schema, vault preview and backup. Keep the comparison reports for the old digest and pick overlap. [Cutover runbook](../runbook/cutover.md#confirm-readiness)

## CLI maintenance

- **Paper retention.** With M4h deployed, the last daily run calls `pnpm exec litscout prune --json --config "$CONFIG"` after the digest and other scheduled writes. Add `--dry-run` to preview kept reasons, eligible papers, sample titles and the budget without writing. [Prune command](../../apps/cli/src/prune-command.ts) · [Daily runbook](../runbook/daily.md#paper-retention)
- **Legacy feed import.** Use `legacy import --dry-run` to preview the approved dates. For the actual import, pass `--keep-rows N` to leave N rows of the day's balance, or `--max-rows N` to cap that run's writes. The importer admits a whole date or linked group at a time and reports progress. Keep the same source and dates on retries. [CLI options](../../apps/cli/src/legacy-command.ts) · [Budgeted importer](../../packages/sync/src/legacy-budgeted.ts) · [Daily runbook](../runbook/daily.md#command-order)
- **Uploads.** The M4i defaults are five papers, twenty summaries, twenty legacy records or twenty radar records per request, with a 256 KiB JSON limit. [Upload defaults](../../packages/core/src/ingest-limits.ts)
- **Repository changes.** The merge gate is local `pnpm verify`. The GitHub Actions workflow can run it by manual dispatch. [Merge checks](../self-host.md#checks-before-merging) · [Scripts](../../package.json) · [Workflow](../../.github/workflows/ci.yml)
